# คุมหลายเครื่องพร้อมกัน (4-5 เครื่อง)

## ปัญหาที่แก้

รีรัน 5 เครื่อง (PC 2 + MacBook 3) คนเดียวดูไม่ไหว
โดยเฉพาะปริศนาจิ๊กซอว์ที่เด้งมาเครื่องไหนก็ได้ ชั่วโมงละครั้ง มีเวลา 5 นาที
ถ้าไม่ได้นั่งจ้องจอนั้นพอดี ก็พลาด

ระบบนี้ให้ **จอเดียวเห็นทุกเครื่อง** และ **โทรศัพท์สั่นทันทีที่มีอะไรต้องทำ**
พร้อมบอกว่าเครื่องไหนและเหลือเวลาเท่าไหร่

---

## โครงสร้าง

```
              ┌──────────────────────────────┐
              │  Hub  (เครื่องไหนก็ได้ 1 เครื่อง)│
              │  จอรวม + สรุปยอดทุกเครื่อง      │
              │  http://<ip-hub>:8700         │
              └──────────────┬───────────────┘
                             ▲  worker ส่งเข้ามา (HTTP ทางเดียว)
        ┌──────────┬─────────┼─────────┬──────────┐
      PC-01      PC-02     MAC-01    MAC-02     MAC-03
     worker     worker     worker    worker     worker
   (ไลฟ์จริง)  (ไลฟ์จริง)  (ไลฟ์จริง) (ไลฟ์จริง) (ไลฟ์จริง)
```

**การเชื่อมต่อเป็นทางเดียว: worker → hub เท่านั้น**

- hub ไม่ต้องรู้ IP ของเครื่องลูก
- เครื่องลูกไม่ต้องเปิด port ทิ้งไว้
- hub ไม่ยิงคำสั่งกลับไปควบคุมเครื่องลูก — มันแค่รับรายงานมาแสดง

ตอบคำถามที่ถามไว้: **ได้ ทุกเครื่องเข้าถึงได้** ขอแค่ต่อ hub ตัวเดียวกัน
Mac กับ PC ใช้โค้ดชุดเดียวกัน ไม่ต้องแยก

---

## ติดตั้ง

### เครื่องที่เป็น hub

จะเป็นเครื่องไหนก็ได้ — ใช้เครื่องที่เปิดทิ้งไว้ตลอดและมี IP นิ่งที่สุด
เครื่องนี้จะรันจอรวมอย่างเดียว ไม่ต้องไลฟ์ (จะไลฟ์ด้วยก็ได้ รันสอง process)

```bash
python -m aiworker --hub
```

เปิด <http://127.0.0.1:8700> บนเครื่องนั้น
หรือจากมือถือในวง Wi-Fi เดียวกัน: `http://<ip-ของเครื่อง-hub>:8700`

หา IP:
- Mac: `ipconfig getifaddr en0`
- Windows: `ipconfig` ดูบรรทัด IPv4 Address

### ทุกเครื่องที่ไลฟ์

แต่ละเครื่องทำ config ของตัวเอง — **ที่ต้องไม่ซ้ำกันมี 3 อย่าง**

```yaml
shop:
  channel_id: "mac-01"          # ช่องที่เครื่องนี้ไลฟ์

verification:
  machine_name: "mac-01"        # ชื่อที่จะขึ้นบนจอรวม

web:
  port: 8765                    # จอของเครื่องตัวเอง (ไม่ต้องเปลี่ยนถ้าคนละเครื่อง)

fleet:
  role: worker
  machine_name: "mac-01"
  hub_url: "http://192.168.1.50:8700"   # IP ของเครื่อง hub
  report_seconds: 5
```

แล้วรันปกติ:

```bash
python -m aiworker --config config/mac-01.yaml
```

## เรื่องเน็ตและ Hub (ตัวกระจายเน็ต)

Hub กระจายเน็ตที่สั่งมาใช้ได้เลย ขอแค่ทุกเครื่องอยู่ **วงเดียวกัน**
(ได้ IP ขึ้นต้นเหมือนกัน เช่น 192.168.1.x ทั้งหมด)

**ข้อควรระวัง 3 ข้อ:**

1. **IP ของเครื่อง hub ต้องไม่เปลี่ยน** ไม่งั้น worker หาไม่เจอ
   ตั้ง DHCP Reservation ในเราเตอร์ผูก IP กับ MAC address ของเครื่องนั้น

2. **Firewall** ครั้งแรกที่รัน `--hub` เครื่องจะถามว่าอนุญาตรับการเชื่อมต่อไหม
   ต้องกดอนุญาต (Mac: System Settings → Network → Firewall)

3. **แบนด์วิดท์** การรายงานสถานะกินน้อยมาก (ไม่กี่ KB ทุก 5 วินาที)
   ตัวที่กินคือการสตรีมวิดีโอ — 5 เครื่องพร้อมกันต้องมีอัปโหลดพอ
   คิดคร่าว ๆ 3-4 Mbps ต่อเครื่อง = ต้องมีอัปโหลดอย่างน้อย 20 Mbps
   ถ้าเน็ตไม่พอจะเห็น bitrate ตกและระบบเตือน "สตรีมมีปัญหา"

## จอรวมแสดงอะไร

เรียงลำดับตามความด่วน ไม่ได้เรียงตามชื่อ:

| ลำดับ | เงื่อนไข |
|---|---|
| 1 | เครื่องที่มีจิ๊กซอว์ค้าง — เหลือเวลาน้อยสุดขึ้นก่อน |
| 2 | เครื่องที่สตรีมดับ |
| 3 | เครื่องที่ขาดการติดต่อ |
| 4 | ที่เหลือ |

แถบแดงบนสุดจะขึ้นเมื่อมีจิ๊กซอว์ค้าง พร้อมนับถอยหลังตัวใหญ่

ด้านบนมีสรุปรวมทุกเครื่อง: ยอดขายรวม, ค่าแอดรวม, **ต้นทุนต่อออเดอร์รวม**,
จำนวนจิ๊กซอว์ที่พลาด

## แจ้งเตือนเข้ามือถือ

จอรวมช่วยตอนนั่งอยู่หน้าจอ แต่ตอนตีสามต้องให้โทรศัพท์สั่น

ตั้ง Telegram ในทุกเครื่อง (ดู `docs/SETUP.md`) แล้วแต่ละเครื่องจะส่งเอง
ข้อความจะบอกชื่อเครื่องและเวลาที่เหลือเสมอ:

```
🆘 [ต้องให้คนจัดการ] จิ๊กซอว์! เครื่อง mac-01 — เหลือ 4.2 นาที
```

ระบบจะปลุกซ้ำแรงขึ้นเรื่อย ๆ ถ้ายังไม่มีใครจัดการ:
ทันที → 45 วินาที → 2 นาที → 3.5 นาที

## เช็คว่าต่อติดหรือยัง

บนเครื่อง hub:

```bash
curl -s http://127.0.0.1:8700/api/fleet | python3 -m json.tool | head -20
```

ควรเห็นทุกเครื่องอยู่ใน `machines` และ `age_seconds` ไม่เกิน 10

**ถ้าเครื่องไหนไม่ขึ้น** ให้เช็คตามลำดับ:

1. บนเครื่องนั้น: `curl http://<ip-hub>:8700/healthz` ต้องตอบ `ok`
   - ไม่ตอบ = ปัญหาเน็ต/firewall ไม่ใช่ปัญหาโปรแกรม
2. `fleet.role` ตั้งเป็น `worker` แล้วหรือยัง
3. `fleet.hub_url` พิมพ์ IP ถูกไหม (ต้องมี `http://` นำหน้า)
4. ดู log ของเครื่องนั้น จะมีบรรทัด "ส่งสถานะเข้า hub ไม่ได้ติดต่อกัน 3 ครั้ง"

**สำคัญ: hub ล่มไม่กระทบไลฟ์** แต่ละเครื่องไลฟ์ต่อได้ปกติ
เสียแค่จอรวมกับสรุปยอด — การแจ้งเตือน Telegram ของแต่ละเครื่องยังทำงาน

## รันหลายเครื่องด้วย config ชุดเดียว

ถ้าไม่อยากทำ config 5 ไฟล์ ใช้ตัวแปรสภาพแวดล้อมช่วยได้:

```bash
# ทุกเครื่องใช้ไฟล์เดียวกัน ต่างกันแค่ชื่อเครื่อง
AIWORKER_CONFIG=config/shared.yaml python -m aiworker
```

แต่ `channel_id`, `machine_name` และคิวชีตของแต่ละช่องมักไม่เหมือนกันอยู่ดี
แนะนำให้แยกไฟล์ต่อเครื่อง แล้วเก็บใน git จะได้ย้อนดูได้ว่าแก้อะไรไป
