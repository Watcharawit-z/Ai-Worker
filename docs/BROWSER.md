# ปักตะกร้าและตอบคอมเมนท์ผ่านเบราว์เซอร์

## ทำไมต้องทำแบบนี้

TikTok ไม่เปิด API ให้ปักตะกร้าและไม่เปิดให้ส่งคอมเมนท์
แต่ทั้งสองอย่างกดได้ในหน้าเว็บ ระบบจึงเปิด Chromium ค้างไว้หนึ่งบาน
ล็อกอินค้างไว้ในโปรไฟล์เดียว แล้วกดปุ่มเดิมที่คนเคยกด

หน้าต่างเดียวใช้ทั้งสองงาน เพราะทั้งช่องคอมเมนท์และลิสต์ตะกร้าอยู่หน้าเดียวกันอยู่แล้ว

## ข้อที่ต้องรู้ก่อนเปิดใช้

**ถ้าปริศนาจิ๊กซอว์โผล่ ระบบจะหยุดมือทันที ไม่กดอะไรในหน้านั้นเลย**
ทั้งการปักตะกร้าและการตอบคอมเมนท์จะหยุดจนกว่าปริศนาจะหายไป
แล้วค่อยทำงานต่อเอง ไม่ต้องสั่งใหม่

ปริศนานั้นมีไว้ตรวจว่ามีคนอยู่จริง ระบบนี้จึงถอยออกมาแล้วปลุกคนแทน
รายละเอียดใน [JIGSAW.md](JIGSAW.md)

## ติดตั้ง

```bash
pip install playwright
playwright install chromium
```

## เก็บ selector (ทำครั้งเดียวต่อเครื่อง)

```bash
python scripts/calibrate_browser.py "https://<หน้าที่ปักตะกร้าได้>"
```

1. เบราว์เซอร์เปิดขึ้นมา — ล็อกอิน TikTok ให้เรียบร้อย
   ล็อกอินจะค้างอยู่ใน `runtime/browser-profile` ครั้งหน้าไม่ต้องล็อกอินใหม่
   **ไม่มีรหัสผ่านอยู่ในไฟล์ config เลย**
2. เปิดหน้าที่ปักตะกร้าและตอบคอมเมนท์ได้
3. สคริปต์จะถามทีละข้อ — **กด Alt ค้างแล้วคลิก** ที่ปุ่มนั้น แล้วกด Enter
4. เอาบล็อกที่มันพิมพ์ออกมาใส่ `config/config.yaml`

ข้อที่ต้องเก็บให้ครบ:

| ชื่อ | คืออะไร | ข้ามได้ไหม |
|---|---|---|
| `product_row` | กรอบของแถวสินค้าหนึ่งรายการ | ไม่ได้ |
| `pin_button` | ปุ่มปักหมุดในแถวนั้น | ไม่ได้ |
| `comment_box` | ช่องพิมพ์คอมเมนท์ | ไม่ได้ (ถ้าจะให้ตอบเอง) |
| `captcha` | กรอบปริศนาจิ๊กซอว์ | ได้ แต่ **ไม่ควรข้าม** |
| `pinned_marker` | เครื่องหมายว่าแถวนี้ปักอยู่ | ได้ (ไว้ตรวจซ้ำว่ากดติดจริง) |
| `comment_send` | ปุ่มส่ง | ได้ (ไม่มีจะใช้ Enter แทน) |

> `captcha` ต้องเก็บตอนที่ปริศนากำลังเด้งอยู่จริง ๆ
> ถ้าไม่เก็บ ระบบจะไม่รู้ว่าต้องหยุดมือตอนไหน — รันสคริปต์ใหม่อีกรอบตอนที่มันเด้งได้

## เปิดใช้

```yaml
adapters:
  shop: browser            # ปักตะกร้า
  comment_sender: browser  # ส่งคำตอบกลับ
  options:
    browser:
      console_url: "https://..."
      dry_run: true        # ← เริ่มที่ true เสมอ
      selectors:
        product_row: "..."
        pin_button: "..."
        comment_box: "..."
        captcha: "..."
```

## `dry_run` — ซ้อมก่อนกดจริง

`dry_run: true` ระบบจะหาปุ่มตามปกติ แล้วเขียนลงล็อกว่า *จะกดอะไร* โดยยังไม่กด

```
[ซ้อม] จะกดปักตะกร้า เซรั่มวิตซี (SKU-B) — ยังไม่กดจริง
[ซ้อม] จะส่งคอมเมนท์: @ploy ราคา 390 ค่ะ — ยังไม่ส่งจริง
```

รันทิ้งไว้สักหนึ่งไลฟ์เต็ม ๆ แล้วไล่ดูว่า:
- ปักตรงกับที่คนในคลิปพูดทุกครั้งไหม
- มี "หาแถวสินค้า ... ในหน้าเว็บไม่เจอ" โผล่บ่อยไหม

ถูกหมดแล้วค่อยเปลี่ยนเป็น `dry_run: false`

## ค่าที่ปรับได้

| ค่า | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `headless` | `false` | ต้องเห็นหน้าต่างไว้ จะได้เข้าไปเลื่อนจิ๊กซอว์ทัน — อย่าเปิดเป็น `true` |
| `slow_mo_ms` | `120` | หน่วงระหว่างการกด ให้ไม่กระตุกผิดมนุษย์ |
| `min_send_interval_seconds` | `3` | ส่งคอมเมนท์ถี่กว่านี้ไม่ได้ |
| `mention_prefix` | `true` | ขึ้นต้นคำตอบด้วย `@ชื่อคนถาม` |
| `timeout_ms` | `8000` | รอ element นานสุดเท่าไหร่ |

## เวลา TikTok เปลี่ยนหน้าเว็บ

จะเกิดขึ้นแน่ ๆ ไม่ช้าก็เร็ว อาการคือล็อกขึ้นรัว ๆ ว่า:

```
หาแถวสินค้า SKU-B (เซรั่ม) ในหน้าเว็บไม่เจอ
```

แก้ด้วยการรัน `scripts/calibrate_browser.py` ใหม่แล้วเปลี่ยน selector

ระบบออกแบบให้ **ตอบว่าไม่สำเร็จ ไม่ใช่แกล้งทำเป็นสำเร็จ** เวลาหาปุ่มไม่เจอ
ปักตะกร้าไม่ได้จะขึ้นเตือนใน dashboard ทันที ไม่ใช่เงียบไปเฉย ๆ แล้วปักผิดทั้งไลฟ์

## ยอดขายยังไม่ได้อ่านจากหน้าเว็บ

`fetch_sales()` ของตัวนี้ตอบว่า "ไม่รู้" เสมอ ตัวเลขบนหน้าไลฟ์อัปเดตช้า
และกวาดมาผิดง่าย ซึ่งอันตรายเพราะตัวเลขนี้เอาไปคิดเพดานค่าแอด
ยอมไม่รู้ดีกว่ารู้ผิดแล้วสั่งสเกลงบ

ถ้าจะให้ยอดขายจริงเข้าระบบ ต้องต่อ TikTok Shop API แยกต่างหาก

## สิ่งที่ตัวนี้ไม่ทำ

- ไม่เลื่อนปริศนาจิ๊กซอว์ และจะหยุดมือเมื่อมันโผล่
- ไม่กดปุ่มอะไรที่ไม่ได้อยู่ในลิสต์ selector ข้างบน
- ไม่เก็บรหัสผ่านลงไฟล์ (ล็อกอินอยู่ในโปรไฟล์เบราว์เซอร์ล้วน ๆ)
