# คู่มือการตัดสินใจ — พนักงาน AI แต่ละคนคิดยังไง

เอกสารนี้อธิบายว่าระบบตัดสินใจอย่างไรในแต่ละสถานการณ์
อ่านก่อนปรับ `config.yaml` จะได้รู้ว่าแต่ละตัวเลขไปกระทบอะไร

---

## 1. พนักงานเฝ้าปริศนาจิ๊กซอว์ (`verify_watcher`)

ปริศนายืนยันตัวตนที่ TikTok เด้งมาตรวจว่ามีคนเฝ้าอยู่ ชั่วโมงละครั้งโดยประมาณ
เดาเวลาไม่ได้ มีเวลาเลื่อน 5 นาที พลาดคือโดนเตือน

**ระบบตรวจจับและปลุกคน ไม่เลื่อนแทน** — เหตุผลและวิธี calibrate อยู่ใน `docs/JIGSAW.md`

| เวลาผ่านไป | ทำอะไร |
|---|---|
| 0 วินาที | แจ้งทุกช่องทาง + ขึ้นแถบแดงบนจอรวม |
| 45 วินาที | เตือนซ้ำ |
| 2 นาที | ยกระดับเป็น critical |
| 3.5 นาที | เตือนรอบสุดท้าย |
| 5 นาที | บันทึกว่าพลาด + แจ้งให้ไปเช็คสถานะช่อง |

ตัวเฝ้าจอเทียบภาพกับตัวอย่างที่เก็บไว้ ต้อง calibrate ก่อนใช้
ถ้ายังไม่ได้ calibrate ระบบจะเตือนตอนเริ่มกะว่าต้องมีคนเฝ้าจอเอง

## 2. พนักงานเฝ้าสตรีม (`live_watcher`)

### ต่อคลิปไม่ให้จอดำ

ทุก 5 วินาทีจะเช็คว่าท่อนปัจจุบันเหลือเวลาเท่าไหร่
เหลือน้อยกว่า 8 วินาที → เริ่มต่อท่อนถัดไปทันที

การเลือกคลิปถัดไป:

```
1. ตัดคลิปที่เพิ่งเล่นไป 3 อันล่าสุดออก (กันวนซ้ำจนคนดูจับได้)
2. สุ่มจากที่เหลือ โดยถ่วงน้ำหนักตาม weight
3. ปักตะกร้าเป็นหน้าที่ของ basket_manager ที่ตามคิวชีตของคลิปนั้น
```

ท่อนที่ขายดีให้ตั้ง `weight: 2.0` ระบบจะหยิบบ่อยขึ้นเป็นสองเท่า

**เงื่อนไขคุม:** ห้ามเปลี่ยนท่อนถ้าเล่นยังไม่ถึง `segment_min_seconds` (ค่าเริ่มต้น 120 วินาที)
กันไม่ให้สลับรัวจนดูผิดปกติ — ยกเว้นกรณีถูกสั่งจากฝ่ายตรวจการละเมิด ซึ่งจะสลับทันที

### เมื่อสตรีมมีปัญหา

| อาการ | ระดับ | ระบบทำอะไร |
|---|---|---|
| ไม่ออกอากาศ | critical | สั่ง start ใหม่เอง → ถ้าไม่สำเร็จ เรียกคนทันที |
| bitrate < 800 kbps | high | บันทึก + เตือน (เน็ตอาจไม่พอ) |
| เฟรมตกเกิน 300 | medium | บันทึก + เตือน |
| มีปัญหาต่อเนื่องเกิน 15 วินาที | high | เรียกคน |

เตือนเรื่องเดิมซ้ำได้ไม่ถี่กว่า 60 วินาที

## 3. พนักงานตอบคอมเมนท์ (`comment_agent`)

### ทางเดินของคอมเมนท์หนึ่งอัน

```
คอมเมนท์เข้ามา
   │
   ├─ ตรงกับ keywords ใน faq?  ──► ตอบทันที (ฟรี ไม่เรียก AI)
   │
   └─ ไม่ตรง ──► รอรวมเป็นชุด (4 วินาที หรือครบ 12 อัน)
                     │
                     └─► ส่งให้ Claude ทีเดียวทั้งชุด
                            │
                            ├─ มั่นใจ ≥ 0.6 และไม่ escalate ──► ตอบ
                            └─ ไม่มั่นใจ / เป็นเรื่องเคลม ──► ส่งต่อให้คน
```

### ทำไมต้องรวมเป็นชุด

1. ถูกกว่า — ยิงทีละอันจ่ายค่า context ซ้ำทุกครั้ง
2. ตอบดีกว่า — AI เห็นคอมเมนท์หลายอันพร้อมกัน เลือกตอบอันที่ควรตอบได้
3. ดูเป็นคนมากกว่า — คนจริงไม่ตอบทุกคอมเมนท์ในหนึ่งวินาที

### กติกาที่บังคับไว้ในโค้ด

- ตอบไม่เกิน 4 อันต่อรอบ (ไม่งั้นดูเป็นบอท)
- คนเดิมตอบซ้ำได้ไม่ถี่กว่า 30 วินาที
- ตัดคำตอบที่ยาวเกิน 120 ตัวอักษร
- คำตอบทุกอันถูกส่งกลับไปให้ฝ่ายตรวจการละเมิดตรวจซ้ำ

### เรื่องที่ AI จะไม่ตอบเอง

ระบบสั่งไว้ในคำสั่งระบบ (system prompt) ให้ส่งต่อคนเสมอเมื่อเจอ:
- เคลมสินค้าเสีย / ขอเงินคืน
- ถามเรื่องออเดอร์เฉพาะราย (ระบบไม่มีข้อมูลนั้น)
- ด่าทอ / เรื่องร้องเรียน
- อะไรที่ไม่มีใน `products.yaml`

## 4. พนักงานเฝ้าการละเมิด (`compliance`)

### หลักการสำคัญที่สุด: แยกว่าใครเป็นคนพูด

| ใครพูด | ระบบทำอะไร |
|---|---|
| **เนื้อหาของเรา** (คำตอบเรา, บทพูดในคลิป) | สลับคลิป / หยุดสตรีม / นับ strike |
| **ผู้ชมพิมพ์เอง** | บันทึกไว้ + บอกคนให้ไปซ่อนคอมเมนท์ — **ไม่สลับคลิป** |

เหตุผล: ถ้าลูกค้าพิมพ์ "ขอไลน์" แล้วเราไปสลับคลิปหนี มันไม่ช่วยอะไรเลย
เพราะคลิปเราไม่ได้ผิด และการสลับรัว ๆ ตามคอมเมนท์จะทำให้ไลฟ์ดูพัง

คอมเมนท์ผู้ชมที่มีปัญหาซ้ำ ๆ จะถูกรวบรายงานครั้งเดียวทุก 2 นาที
พร้อมบอกว่าซ้ำกี่ครั้ง

### สองด่าน

**ด่านที่ 1 — regex** (ทันที ไม่มีค่าใช้จ่าย)

จับ: ชวนไปไลน์/เฟส, ให้เลขบัญชี, เบอร์โทร, ลิงก์ภายนอก,
อ้างรักษาโรค, อ้าง 100%, อ้าง อย. รับรอง, คำต้องห้ามที่ร้านตั้งเอง

**ด่านที่ 2 — Claude อ่านบริบท** (ทุก 90 วินาที)

จับสิ่งที่ regex จับไม่ได้ เช่นพูดอ้อม ๆ ให้ไปซื้อที่อื่น
หรือเคลมสรรพคุณด้วยคำที่เลี่ยงไปแล้ว

ระบบย้ำในคำสั่งว่า **อย่าตื่นตูม** — การขายของปกติไม่ใช่การละเมิด

### เจอแล้วทำอะไร (เฉพาะเนื้อหาของเรา)

| ระดับ | การกระทำ |
|---|---|
| low / medium | บันทึกไว้เฉย ๆ |
| high | สลับท่อนวิดีโอทันที + แจ้งคน |
| critical | หยุดสตรีม + เรียกคนด่วน + พักแอด |

เว้นอย่างน้อย 30 วินาทีระหว่างการลงมือแต่ละครั้ง กันสั่งรัว

ปรับเกณฑ์ได้ที่ `compliance.auto_switch_segment_at` และ `auto_stop_at`

## 5. พนักงานปักตะกร้า (`basket_manager`)

### หลักการเดียว: ตะกร้าเดินตามปาก ไม่ได้เดินตามนาฬิกา

รีรันคือการเปิดคลิปที่อัดไว้ คนในคลิปพูดถึงสินค้าตัวไหน เราปักตัวนั้น
ระบบไม่มีตรรกะ "ขายไม่ดีให้เปลี่ยนสินค้า" เพราะนั่นคือไลฟ์สด ไม่ใช่รีรัน

### ทางเดินของการปัก

```
ทุก 5 วินาที
   │
   ├─ เล่นคลิปมาถึงวินาทีที่เท่าไหร่?
   │     └─ ปกติเชื่อค่าจากตัวเล่น (แม่นกว่าจับเวลาเอง)
   │        ยกเว้นช่วงนาทีแรกหลังเปลี่ยนท่อน ที่ค่านั้นอาจเป็นของเก่าค้าง
   │
   ├─ คิวชีตบอกว่าตอนนี้ (+2 วินาที) พูดถึง SKU ไหน?
   │
   ├─ ตรงกับที่ปักอยู่แล้ว → ไม่ทำอะไร
   ├─ ไม่มีตะกร้าของ SKU นั้น → เตือนคนหนึ่งครั้ง แล้วปล่อยผ่าน
   └─ มี → ปักขึ้นแสดง
```

**ทำไมปักล่วงหน้า 2 วินาที:** ปักช้ากว่าปากคือคนดูกดตะกร้าแล้วเจอของผิดตัว
ปักเร็วไปนิดไม่มีใครสังเกต — ผิดพลาดไปทางที่เสียหายน้อยกว่า

**ทำไมมีตัวกันค่าค้าง:** ตอนเปลี่ยนท่อน ตัวเล่นอาจยังรายงานเวลาที่เหลือ
ของท่อนเก่าอยู่หนึ่งรอบ ถ้าเชื่อทันทีจะคำนวณว่าเล่นมาเกือบจบแล้ว
แล้วปักตะกร้าของช่วงท้ายคลิปทั้งที่เพิ่งเริ่ม (บั๊กจริงที่เจอตอนทดสอบ)

### เรื่องที่เตือนคน

| เจออะไร | ทำอะไร |
|---|---|
| คลิปพูดถึง SKU ที่ไม่มีตะกร้า | เตือนหนึ่งครั้งต่อ SKU — คนดูจะหาของไม่เจอ |
| ของที่ปักอยู่หมดสต็อก | เตือนให้เติมของหรือเอาตะกร้าออก |
| ตะกร้าที่ไม่มีคลิปพูดถึงเลย | `--check` บอกตั้งแต่ก่อนเข้ากะ |

### เตรียมคิวชีต

ทำครั้งเดียวต่อคลิป: เปิดคลิปดู จดเวลาที่เริ่มพูดถึงสินค้าแต่ละตัว
ไม่ต้องละเอียดถึงวินาที ±10 วินาทีพอ แต่ให้ "ปักก่อนพูด" ดีกว่าปักช้า

รองรับสองแบบ: คลิปยาวไฟล์เดียว + คิวชีต (ตรงกับรีรันจริงที่สุด)
หรือตัดเป็นท่อนละสินค้าแล้วใส่ `sku` ที่ท่อนเลย

## 6. พนักงานดูแลแอด (`ads_manager`)

ตรรกะเป็นโค้ดล้วน **ไม่เรียก AI** เพราะเรื่องเงินต้องคาดเดาได้และอธิบายได้

### แอดผูกกับไลฟ์ ไม่ใช่ตะกร้า

```
ขึ้นไลฟ์ใหม่ ──► ขึ้น GMV Max Live หนึ่งตัว งบ 300฿

เปลี่ยนตะกร้าที่ปัก ──► ไม่แตะแอดเลย

ทุก 60 วินาที ดึงตัวเลขมาดู
   │
   ├─ แอดขึ้นยังไม่ถึง 20 นาที ──► ยังไม่ตัดสิน (ตัวเลขยังไม่นิ่ง)
   ├─ ใช้ยังไม่ถึง 150฿        ──► ยังไม่ตัดสิน
   │
   ├─ CPA > 120฿ ──► ปิดตัวเก่า ขึ้นตัวใหม่ในไลฟ์เดิม
   │                  (เว้น 30 นาทีก่อนเปลี่ยนอีกครั้ง)
   │                  เปลี่ยนครบ 3 ครั้งยังแพง → หยุด เรียกคน
   │
   └─ CPA ≤ 70฿  ──► คูณงบ 1.3 เท่า (เพดาน 2,000฿)
```

### ทำไมใช้ CPA ไม่ใช่ ROAS

ไลฟ์นายหน้ากำไรต่อชิ้นบาง ยอดขายรวมสูงไม่ได้แปลว่าได้กำไร
ถ้าค่าแอดต่อออเดอร์แพงกว่าค่าคอมที่ได้ ยิ่งขายยิ่งขาดทุน
CPA เทียบกับค่าคอมต่อชิ้นได้ตรง ๆ — ตั้ง `max_cpa` ให้ต่ำกว่าค่าคอมเสมอ

### กรณีใช้เงินแล้วไม่ได้ออเดอร์เลย

ไม่ต้องรอให้มีออเดอร์ก่อนถึงจะคำนวณ CPA ได้
ถ้าใช้ไปเกิน `max_cpa × min_purchases` แล้วยังไม่มีออเดอร์
แปลว่าต่อให้ได้ออเดอร์ตอนนี้ CPA ก็เกินเพดานแน่นอน → ปิดเลย

### ปรับให้เข้ากับงานคุณ

| ถ้าคุณ | ปรับ |
|---|---|
| ค่าคอมต่อชิ้นต่ำ | `max_cpa` ต่ำลง, `target_cpa` ต่ำลง |
| อยากดันแรง | `scale_step` เป็น 1.5, `max_budget` สูงขึ้น |
| แอดโดนปิดเร็วเกินไป | เพิ่ม `grace_minutes_after_launch` หรือ `min_spend_before_judging` |
| เปลี่ยนแอดวนไม่จบ | เพิ่ม `relaunch_cooldown_minutes` หรือลด `max_relaunches_per_live` |

## 7. คนแจ้งเตือน (`notifier`)

ส่งเฉพาะระดับ medium ขึ้นไป หรือที่ติดธง "ต้องให้คนจัดการ"
เรื่องเดิมส่งซ้ำได้ไม่ถี่กว่า 5 นาที

**เรื่องที่จะถึงมือคนแน่นอน:**
- สตรีมดับ / กู้ไม่ได้
- พบความเสี่ยงระดับ high ขึ้นไปในเนื้อหาของเรา
- คลิปหมดคิว
- คลิปพูดถึงสินค้าที่ไม่มีตะกร้า
- จิ๊กซอว์โผล่ และจิ๊กซอว์ที่พลาดไป
- แอดถูกปิดเพราะไม่คุ้ม
- ยิงแอดไม่สำเร็จ

---

## สิ่งที่ระบบ *ไม่* ตัดสินใจเอง

ตั้งใจออกแบบให้เป็นแบบนี้ — งานพวกนี้ยังต้องเป็นคน:

- เพิ่มงบเกิน `max_budget`
- เปลี่ยนราคาสินค้า
- ตอบเรื่องเคลม / คืนเงิน
- เริ่มสตรีมใหม่หลังถูกสั่งหยุดเพราะความเสี่ยงร้ายแรง
- ตัดสินใจว่าจะเลิกใช้ช่องที่โดนเตือนซ้ำ ๆ

---

## ปรับจูนจากของจริง

หลังใช้ไปสักกะสองกะ ดูตัวเลขบน dashboard แล้วปรับ:

| เห็นอะไร | ควรทำอะไร |
|---|---|
| อัตราตอบอัตโนมัติต่ำกว่า 50% | เติม `faq` และรายละเอียดใน `products.yaml` |
| ส่งต่อให้คนเยอะมาก | ดูว่าคำถามซ้ำ ๆ อะไร แล้วเติมเข้า `faq` |
| ปักตะกร้าไม่ตรงกับที่คลิปพูด | คิวชีตคลาดเคลื่อน จดเวลาใหม่ให้ตรง |
| แอดถูกเปลี่ยนบ่อย | `max_cpa` ต่ำเกินจริง หรือคลิปไม่ปิดการขาย |
| จิ๊กซอว์พลาดบ่อย | เวลาตอบสนองช้า — เพิ่มช่องทางแจ้งเตือน |
| ค่า AI สูงกว่าที่รับได้ | ตั้ง `llm.effort: low`, เพิ่ม `batch_seconds`, เติม `faq` |
| strike ของเราเองมากกว่า 0 | ไปดูว่าคำตอบไหนผิดกฎ แล้วแก้ system prompt หรือ `products.yaml` |
