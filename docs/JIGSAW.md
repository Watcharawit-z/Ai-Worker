# ปริศนาจิ๊กซอว์ — สิ่งที่ระบบทำและไม่ทำ

## ข้อสรุปสั้น ๆ

**ระบบตรวจจับและปลุกคน — ไม่เลื่อนปริศนาแทน**

ปริศนานี้คือกลไกที่ TikTok ใช้ตรวจว่ามีคนเฝ้าไลฟ์อยู่จริง
การเขียนโปรแกรมให้เลื่อนแทนคือการปิดตากลไกนั้นโดยตรง โปรเจกต์นี้จึงไม่มีส่วนนั้น
ไม่ว่าจะรูปแบบไหน — เรียก AI มาเลื่อน, ลงเป็นโปรแกรมในเครื่อง, หรือให้เข้าถึงเครื่องได้

ตัวเฝ้าจอในระบบนี้อ่านภาพอย่างเดียว ไม่มีโค้ดส่วนไหนควบคุมเมาส์หรือคีย์บอร์ด
ถ้าจะต่อยอดเอง โปรดรู้ว่าโครงสร้างไม่ได้เตรียมไว้ให้ทำแบบนั้น

## สิ่งที่ระบบทำแทนได้จริง

งานที่หนักไม่ใช่การลากเมาส์ 2 วินาที แต่คือ **การเฝ้า 5 จอตลอด 24 ชั่วโมง
รอสิ่งที่มาชั่วโมงละครั้งแบบเดาไม่ได้** ตรงนั้นเครื่องทำได้ดีกว่าคนมาก

| งาน | คนทำเอง | ระบบทำ |
|---|---|---|
| เห็นว่าปริศนาโผล่ | ต้องจ้องจอนั้นพอดี | 3 วินาที |
| รู้ว่าเครื่องไหน | ต้องไล่ดูทีละเครื่อง | บอกชื่อเครื่องทันที |
| รู้ว่าเหลือเวลาเท่าไหร่ | เดาเอง | นับถอยหลังจริง |
| ปลุกตอนตีสาม | ต้องตั้งนาฬิกาปลุกมั่ว ๆ | โทรศัพท์สั่นทันที + ย้ำเรื่อย ๆ |
| รู้ว่าของจริงหรือเตือนผิด | ต้องลุกไปดูจอ | ส่งภาพจิ๊กซอว์เข้า Telegram ให้ดูจากเตียง |
| รู้ว่าพลาดไปกี่ครั้ง | จำไม่ได้ | มีสถิติ |

เวลาตอบสนองที่คาดหวัง: เห็นภายใน 3 วินาที + แจ้งทันที
เหลือเวลาให้เดินไปเลื่อนอีก ~4.5 นาทีจาก 5 นาทีที่ได้

## จังหวะการปลุก

ยิ่งใกล้หมดเวลา ยิ่งดังขึ้น — กันกรณีเผลอปิดการแจ้งเตือนครั้งแรก

| เวลาผ่านไป | ทำอะไร |
|---|---|
| 0 วินาที | แจ้งทันทีทุกช่องทาง + ขึ้นแถบแดงบนจอรวม |
| 45 วินาที | ยังไม่มีใครจัดการ — เตือนซ้ำ |
| 2 นาที | เหลือเวลาไม่ถึงครึ่ง — ยกระดับเป็น critical |
| 3.5 นาที | ใกล้หมดเวลา — เตือนรอบสุดท้าย |
| 5 นาที | บันทึกว่าพลาด + แจ้งให้ไปเช็คสถานะช่อง |

ปรับได้ที่ `DEFAULT_ESCALATION` ใน `src/aiworker/domain/verification.py`

## ตั้งค่าตัวเฝ้าจอ

ตัวจับปริศนาทำงานด้วยการเทียบภาพ ต้องสอนให้มันรู้จักหน้าตาปริศนาก่อน

```bash
pip install mss pillow
python scripts/calibrate_screen.py
```

เครื่องมือจะบอกให้รอจนปริศนาโผล่ แล้วกด Enter เพื่อเก็บภาพ
**เก็บ 3-5 ภาพจากคนละครั้งจะแม่นที่สุด** เพราะตำแหน่งชิ้นส่วนไม่เหมือนกันทุกครั้ง

จากนั้นเอาค่าที่มันพิมพ์ออกมาใส่ใน `config.yaml`:

```yaml
verification:
  watcher: template

adapters:
  options:
    screen:
      region: [0, 0, 1920, 1080]
      threshold: 0.82
      templates:
        - "config/reference/puzzle_01.png"
        - "config/reference/puzzle_02.png"
```

ต้องทำแยกทุกเครื่อง เพราะความละเอียดจอและตำแหน่งหน้าต่างไม่เหมือนกัน
ถ้าเปลี่ยนความละเอียดจอหรือย้ายหน้าต่าง ต้อง calibrate ใหม่

**ภาพจิ๊กซอว์จะถูกแนบไปกับการแจ้งเตือน Telegram อัตโนมัติ**
เปิดดูจากมือถือได้เลยว่าเป็นปริศนาจริงหรือระบบเตือนผิด — ลดการลุกไปดูเปล่า ๆ
ภาพเก็บไว้ที่ `runtime/snapshots/` เก็บล่าสุด 20 ภาพแล้วลบของเก่าอัตโนมัติ

## จูนความแม่น

| อาการ | แก้ |
|---|---|
| ปริศนาโผล่แต่ระบบไม่จับ | ลด `threshold` ทีละ 0.05 (ต่ำสุดที่ควรใช้ 0.70) |
| เตือนทั้งที่ไม่มีปริศนา | เพิ่ม `threshold` ทีละ 0.05 |
| จับได้บ้างไม่ได้บ้าง | เก็บภาพตัวอย่างเพิ่มอีก 2-3 ภาพ |
| ไม่เวิร์กเลย | ลด `region` ให้แคบลง เอาเฉพาะบริเวณที่ปริศนาโผล่ |

**ทดสอบก่อนไว้ใจ:** รัน `--minutes 90` แล้วรอปริศนาครั้งถัดไป
อย่าเพิ่งเอาคนออกจากการเฝ้าจนกว่าจะเห็นว่ามันจับได้จริงติดต่อกันหลายครั้ง

ระหว่างที่ยังไม่ได้ calibrate ระบบจะเตือนตอนเริ่มกะว่า
"ตัวเฝ้าจอยังใช้ไม่ได้ ต้องมีคนเฝ้าจอเองตลอด" — อย่ามองข้ามบรรทัดนั้น

## ถ้าพลาดไปแล้ว

ระบบจะแจ้งว่า "พลาดปริศนายืนยันตัวตน" พร้อมชื่อเครื่อง

สิ่งที่ควรทำ:
1. เข้าไปดูสถานะช่องว่าโดนเตือนหรือหลุดไลฟ์ไปแล้ว
2. ถ้าหลุด ให้เปิดไลฟ์ใหม่ (แอดจะขึ้นใหม่อัตโนมัติเมื่อรันระบบใหม่)
3. ดูสถิติบนจอรวมว่าเครื่องไหนพลาดบ่อย — ปกติแปลว่าเวลาตอบสนองช้าเกินไป
   ลองย้ายเครื่องนั้นไปไว้ใกล้ตัว หรือเพิ่มช่องทางแจ้งเตือน
