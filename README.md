# Ai-Worker — พนักงาน AI แผนกรีรันไลฟ์ TikTok

ระบบพนักงาน AI ที่รับงานแทนคนในแผนกรีรันไลฟ์ ตามโครงสร้างทีมในสไลด์:
เฝ้าไลฟ์ · ต่อจิ๊กซอว์ · ตอบคอมเมนท์ · สังเกตการละเมิด · จัดการตะกร้า 10 ใบ · ดูแลแอด

**พนักงานไลฟ์ (คนพูดหน้ากล้อง) ยังเป็นคนเหมือนเดิม** — ระบบนี้ไม่ยุ่งกับตรงนั้น

---

## เริ่มใน 3 คำสั่ง

```bash
pip install -r requirements.txt
export PYTHONPATH=src                      # หรือ pip install -e .
python -m aiworker --config config/demo.yaml --minutes 3
```

เปิด <http://127.0.0.1:8765> เพื่อดูว่าพนักงาน AI แต่ละคนกำลังทำอะไร

โหมด demo ใช้ข้อมูลจำลองทั้งหมด — ยังไม่ต้องต่อ TikTok, ไม่ต้องมี API key,
ไม่มีอะไรถูกส่งออกไปข้างนอก ปลอดภัยที่จะกดรันดูเลย

ให้ AI ตอบคอมเมนท์ด้วย: คัดลอก `.env.example` เป็น `.env` แล้วใส่ `ANTHROPIC_API_KEY`

## พนักงาน AI ในแผนกนี้

| พนักงาน | แทนงานอะไร | ตัดสินใจเองได้แค่ไหน |
|---|---|---|
| `live_watcher` | เฝ้าไลฟ์ + ต่อจิ๊กซอว์ | ต่อ/สลับท่อนวิดีโอ, กู้สตรีมที่หลุด |
| `comment_agent` | ตอบคอมเมนท์ลูกค้า | ตอบเองเมื่อมั่นใจ ไม่มั่นใจส่งต่อคน |
| `compliance` | สังเกตการละเมิด | สั่งสลับท่อน / สั่งหยุดสตรีม + เรียกคน |
| `basket_manager` | ดูแลช่อง + คิวตะกร้า 10 ใบ | เปลี่ยนตะกร้าตามเวลาและยอดขาย |
| `ads_manager` | ยิงแอด | ขึ้นแอดใหม่, สเกลตอนติด, ปิดตอนไม่คุ้ม |
| `notifier` | ส่งเรื่องถึงคน | เฉพาะเรื่องระดับ medium ขึ้นไป |

ทุกคนคุยกันผ่าน event bus ไม่มีใครเรียกใครตรง ๆ — ถอดหรือเพิ่มพนักงานได้โดยไม่กระทบตัวอื่น

```
คอมเมนท์เข้า ──► comment_agent ──► ตอบกลับ
                      │
                      ▼
                 compliance ──► สั่งสลับท่อน / หยุดสตรีม
                      │                  │
                      ▼                  ▼
                 notifier          live_watcher ──► ต่อจิ๊กซอว์
                                          ▲
basket_manager ──► ขึ้นตะกร้าใหม่ ────────┤
       │                                  │
       └──────────► ads_manager ──► ขึ้น/สเกล/ปิดแอด
```

## กฎที่ระบบใช้ตัดสินใจ

ทั้งหมดปรับได้ใน `config/config.yaml` ไม่ต้องแตะโค้ด

**ตะกร้า** — ตามที่สไลด์เขียนว่า *"สังเกตยอดขาย ภายใน 1 ชม."*
- ไม่ถึง 20 นาที → ห้ามเปลี่ยน (ยังไม่พอตัดสิน)
- ครบ 60 นาที → ตัดสิน: ได้ต่ำกว่า 3 ออเดอร์ = เปลี่ยนตะกร้า
- ครบ 90 นาที → เปลี่ยนแน่นอน แม้ยอดจะดี (กันคนดูเบื่อ)
- ติดแรงตั้งแต่ต้น (ออเดอร์เกิน 3 เท่าเกณฑ์) → บอกฝ่ายแอดให้สเกลทันที
- ของหมดสต็อก → เปลี่ยนทันที

**แอด** — ตามที่สไลด์เขียนว่า *"ดูแอดว่าค่าแอดแพงไหม ไปต่อได้รึป่าว"*
- ขึ้นตะกร้าใหม่ → ปิดแคมเปญเดิม เปิดใหม่ที่งบ 300฿
- ใช้ยังไม่ถึง 150฿ → ยังไม่ตัดสิน (ตัวเลขยังไม่มีความหมาย)
- ROAS ≥ 3.0 → คูณงบ 1.5 เท่า (เพดาน 3,000฿)
- ROAS < 1.2 → ปิดแอดทันที + แจ้งเจ้าของ

**การละเมิด** — สองด่าน
- ด่านเร็ว: regex จับคำเสี่ยงทุกคอมเมนท์ทันที ไม่มีค่าใช้จ่าย
  (ชวนไปไลน์, ให้เลขบัญชี, อ้างสรรพคุณรักษาโรค, ลิงก์ภายนอก, คำต้องห้ามที่คุณตั้งเอง)
- ด่านลึก: ให้ AI อ่านบริบทย้อนหลังทุก 90 วินาที จับสิ่งที่ regex จับไม่ได้
- เจอระดับ `high` → สลับท่อนวิดีโอหนี · เจอ `critical` → หยุดสตรีม + เรียกคนทันที

**ต่อจิ๊กซอว์**
- ต่อท่อนถัดไปก่อนท่อนปัจจุบันจบ 8 วินาที — ไม่ให้จอดำแม้แต่วินาทีเดียว
- เลือกเฉพาะท่อนที่ตรงกับ SKU ของตะกร้าที่ขึ้นอยู่
- ห้ามหยิบท่อนซ้ำภายใน 3 ท่อนล่าสุด
- สุ่มตามน้ำหนัก — ท่อนที่ขายดีตั้ง `weight` สูงไว้ ระบบจะหยิบบ่อยขึ้น

## เตรียมข้อมูลก่อนใช้จริง

| ไฟล์ | ใส่อะไร |
|---|---|
| `config/config.yaml` | เกณฑ์ตัดสินใจทั้งหมด |
| `config/baskets.yaml` | ตะกร้า 10 ใบ เรียงตามคิว |
| `config/segments.yaml` | ท่อนวิดีโอที่ตัดไว้ + SKU ของแต่ละท่อน |
| `config/knowledge/products.yaml` | ข้อมูลสินค้า + คำตอบสำเร็จรูป |
| `.env` | API key และช่องทางแจ้งเตือน |

ตรวจว่าครบหรือยัง:

```bash
python -m aiworker --check
```

**ข้อสำคัญเรื่องคลิป:** ระบบตอบตามข้อมูลใน `products.yaml` เท่านั้น
อะไรที่ไม่ได้เขียนไว้ มันจะไม่เดา แต่จะส่งต่อให้คน — เขียนละเอียดได้ ไม่เปลือง
เพราะส่วนนี้ถูก cache ไว้ (จ่ายเต็มครั้งเดียว ครั้งต่อไปถูกลง ~10 เท่า)

## ต่อของจริง

แก้ `adapters` ใน `config.yaml` ทีละตัว อย่าเปลี่ยนพร้อมกันหมด

**OBS Studio** (`player: obs`) — `pip install obsws-python`
1. Tools → WebSocket Server Settings → เปิด Enable + ตั้งรหัสผ่าน
2. สร้าง Scene ชื่อ `RERUN` ใส่ Media Source ชื่อ `SEGMENT` ไว้ข้างใน
3. ใส่รหัสผ่านใน `adapters.options.obs.password`

**คอมเมนท์ TikTok** (`comments: tiktok`) — `pip install TikTokLive`
ใส่ชื่อบัญชีใน `adapters.options.tiktok.unique_id`

> ⚠️ TikTok ไม่มี API สาธารณะสำหรับ **ส่ง** คอมเมนท์กลับเข้าไลฟ์
> ระบบจึงเข้าคิวคำตอบไว้ให้คนกดคัดลอกส่งแทน (เร็วกว่าคิดเองมาก แต่ยังต้องมีคนอยู่)
> การใช้เครื่องมือพิมพ์อัตโนมัติแทนคนเสี่ยงผิดข้อตกลงการใช้งาน — ระบบนี้ไม่ทำให้

**ระบบร้าน / ระบบแอด** — ยังเป็น mock ทั้งคู่
TikTok Shop และ TikTok Ads API ต้องสมัคร developer account ก่อน
เขียนคลาสตาม `ShopAdapter` / `AdsAdapter` ใน `src/aiworker/adapters/base.py`
แล้วลงทะเบียนใน `registry.py` — โครงรอไว้ให้แล้ว

**แจ้งเตือน** — `notify: [console, telegram]` แล้วใส่ token ใน `.env`

## ค่าใช้จ่าย

| รายการ | ประมาณการ |
|---|---|
| ตอบคอมเมนท์ (ไลฟ์ 8 ชม. คอมเมนท์ ~40/นาที) | $1.5 – 4 / วัน |
| ตรวจการละเมิดเชิงบริบท (ทุก 90 วิ) | $0.5 – 1.5 / วัน |
| เฝ้าไลฟ์ / ตะกร้า / แอด | ฟรี (ไม่เรียก AI) |
| **รวม** | **ราว 70 – 200 บาท/วัน ต่อช่อง** |

ตัวเลขจริงดูได้บนหน้า dashboard ช่อง "ค่าใช้จ่าย AI" แบบเรียลไทม์

วิธีลดค่าใช้จ่าย:
- เพิ่มคำตอบใน `faq` ให้เยอะ (ตอบจากคลังไม่เสียเงินเลย)
- ตั้ง `comments.batch_seconds` สูงขึ้น (รวมหลายคอมเมนท์ยิงทีเดียว)
- ตั้ง `llm.effort: low`
- ตั้ง `compliance.llm_review_interval_seconds` ให้ห่างขึ้น

## ข้อจำกัดที่ต้องรู้ก่อนใช้

1. **ยังต้องมีคนอยู่** ระบบส่งงานที่ตัดสินใจเองไม่ได้กลับมาให้คน
   ตั้งเป้าให้คนหนึ่งคนดูแลได้หลายช่องพร้อมกัน ไม่ใช่ไม่มีคนเลย
2. **ส่งคอมเมนท์กลับต้องคนกด** ตามที่อธิบายข้างบน
3. **การรีรันมีความเสี่ยงเรื่องนโยบายแพลตฟอร์ม** ระบบช่วยลดความเสี่ยงจากเนื้อหา
   แต่ไม่ได้การันตีว่าจะไม่โดนตรวจสอบ — ส่วนนี้อยู่นอกเหนือที่โค้ดจะควบคุมได้
4. **ระบบร้านและแอดยังเป็นข้อมูลจำลอง** ตัวเลขยอดขายบน dashboard ยังไม่ใช่ของจริง
   จนกว่าจะเขียน adapter ต่อ API จริง
5. **ทดสอบด้วย `--minutes` ก่อนเสมอ** อย่าเพิ่งปล่อยรันทั้งกะในครั้งแรก
